# ADR 0235 — CAST expression

## Status

Accepted.

## Context

SELECT often needs explicit type conversion: parse a stored
text column as an integer, format a numeric for display, cast
a column for an aggregation.

## Decision

`FuncExpr::Cast { arg, target }` where target is a `DataType`.
Grammar `CAST(arg AS type)`; the type name admits `INT`,
`BIGINT`, `TEXT`, `BOOLEAN`, `JSON` (and the usual aliases
`INTEGER`, `INT4`, `INT8`, `BOOL`). Conversion rules in
`cast_value`:

- NULL passes through unchanged.
- Boolean → from bool, int, text ('true'/'false'/'0'/'1').
- Int32 → from Int32/Int64/Decimal (overflow rejects),
  text parse, bool.
- Int64 → symmetric to Int32.
- Text → from text / numeric (`to_string`) / bool / JSON.
- Json → from JSON or well-formed JSON text.
- Any other pair rejects with `SqlError::Type`.

## Consequences

- No Decimal / TimestampTz / Uuid casts yet (those need scale
  / format decisions). Reserved for a dedicated ADR.
- CAST composes with the other scalar functions via the ADR
  0234 nested args path (`CAST(UPPER(s) AS INT)` is legal but
  typically fails at value-level validation).
