# ADR 0270 + 0272 + 0273 — IN subquery, column-column WHERE, INNER JOIN (verification)

## Status

Accepted.

## Context

Three P0-3 line-items in the gap plan were claimed as "open"
but were in fact already shipped in earlier ADRs:

- **IN (SELECT …)** via ADR 0229's `resolve_in_subqueries`
  — the outer IN gets its RHS replaced with the subquery's
  literal results before dispatch.
- **Column-in-column WHERE across a JOIN** — covered by
  ADR 0226's JOIN with `ON a.col = b.col` predicate.
- **INNER JOIN** — covered by ADR 0226.

Each had a parser + evaluator but no top-level verification
tests in the integration suite.

## Decision

Pin the behavior with a single verification file
`tests/p0_3_verification.rs`:

1. IN subquery narrows the outer set.
2. IN subquery with a predicate inside the subquery.
3. INNER JOIN on equality produces the matched rows.
4. INNER JOIN excludes non-matching rows.

No new code.

## Consequences

- The three P0-3 items are closed to verification. Their
  implementation evidence stays in ADRs 0229 and 0226.
- A separate gap (LEFT / RIGHT / FULL JOIN; correlated
  subqueries; multi-column IN subqueries) remains open —
  tracked in the main plan as follow-ups beyond the strict
  P0-3 scope.
- 4 tests in `tests/p0_3_verification.rs`.
