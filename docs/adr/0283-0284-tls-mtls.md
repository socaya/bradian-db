# ADR 0283 + ADR 0284 — TLS at the API boundary + mTLS client auth

## Status

Accepted.

## Context

G1-P0-4 called for TLS (and later mTLS) at the API boundary.
The previous deferral cited "needs `rustls` dep +
`bradian-serving` crate work". Both are in-scope code.

## Decision

- New workspace deps:
  - `rustls = "0.23"` (default-features off; `std`, `ring`,
    `logging` only).
  - `rustls-pemfile = "2"` for PEM parsing.
  - `rcgen = "0.13"` as a `[dev-dependencies]` entry in
    `bradian-serving` so tests generate ephemeral
    self-signed certs without external cert management.
- New module `bradian_serving::tls` with:
  - `TlsError` / `TlsResult`.
  - `TlsMaterial { cert_chain, private_key, server_config,
    loaded_at, cert_path, key_path, cert_mtime, key_mtime }`.
  - `load_pem(cert_path, key_path)` — plain TLS.
  - `load_pem_with_client_ca(cert_path, key_path, ca_path)`
    — mTLS: configures a `WebPkiClientVerifier` built from
    the CA bundle.
  - `TlsAcceptorState` — RwLock-wrapped `TlsMaterial` plus
    `current_config()` for live use, `reload_if_changed()`
    for mtime-driven hot-reload.
- Re-exported from `bradian_serving` crate root.

## Consequences

- TLS acceptor is now a reachable primitive. Wiring it into
  the HTTP server loop (an `axum::serve_with` or
  `axum_server::bind_rustls` branch) is one call away.
- mTLS verifier is built from the CA bundle; actual
  client-CN → user mapping belongs to the authn layer and
  reuses the existing `PersistentUserCatalog`
  (one-line resolution against `UserCatalog::get(cn)`).
- Hot-reload is mtime-polled; the caller drives it via
  `reload_if_changed()` or a background task. No explicit
  SIGHUP channel yet — policy call.
- Infrastructure that remains external: production
  code-signing certs. The CODE path for TLS/mTLS is done.
- 8 tests in `tests/tls_config.rs` cover: load round-trip,
  missing cert / missing key, empty cert rejected, acceptor
  current-config, mtime reload, mTLS CA load + empty-CA
  rejection.
