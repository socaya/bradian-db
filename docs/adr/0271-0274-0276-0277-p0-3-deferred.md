# ADR 0271 + 0274 + 0276 + 0277 — P0-3 slices deferred past this autonomous run

## Status

Accepted (as a scope declaration). Each sub-slice stays
`OPEN` in the Platform Gaps Plan.

## Context

The autonomous Gate 1 completion run shipped seven P0-3
slices (ADRs 0239, 0240, 0243, 0244, 0245, 0246, 0257, 0262,
0263, 0268, 0270, 0272, 0273, 0275). Four P0-3 items are
documented but DEFERRED because they require design work
beyond the scope of a single-session autonomous run:

- **ADR 0271 — EXISTS subquery in WHERE.** Requires either
  a new `WhereTree::Bool` variant with engine-coupled
  pre-evaluation at parse time, or a textual rewrite that
  short-circuits the outer to a zero-row result when EXISTS
  is empty (needs outer-SELECT reshape awareness). Design
  path captured below.
- **ADR 0274 — CTE (`WITH … AS (SELECT …)`).** Requires a
  per-session name registry and inline substitution. Shape
  matches the IN-subquery rewrite (ADR 0229) but keeps the
  bound result across multiple referenced sites in the
  outer statement.
- **ADR 0276 — Full isolation qualification.** ANSI-reference
  schedule suite + write-skew matrix. Requires a scripted
  harness that the P0-5 fault-injection track provides
  primitives for; the schedule corpus itself is a separate
  deliverable.
- **ADR 0277 — External SQL-92/99/2016 conformance suite.**
  Requires importing, adapting, and running an external
  reference suite (SQLLogicTest, pgTAP, or equivalent).
  Infrastructure work; not a code slice.

## Decision

Keep each item's design note here so a future implementer
doesn't repeat the dead-ends:

### EXISTS (ADR 0271 target)

Cleanest path: extend `WhereTree` with
`Bool(bool)` variant. Add a pre-parse textual pass that
locates `EXISTS (SELECT …)`, executes the inner through
the engine, and substitutes the outer SQL so the result is
a tautology or contradiction:

- Non-empty → replace with `WHERE … AND <pk_col> = <pk_col>`
  (always true if the outer has a PK; the base engine's
  scalar WHERE accepts bare-column compares after ADR 0245).
- Empty → replace with `WHERE … AND <pk_col> <> <pk_col>`
  (always false).

Open design question: EXISTS inside OR / NOT — either wait
for the tree-parser extension OR limit to AND-of-EXISTS and
reject the rest.

### CTE (ADR 0274 target)

Textual substitution before dispatch: given
`WITH n AS (<SELECT>) <OUTER>`, parse `n` and the inner
SELECT, store `n → (result)`, then rewrite `<OUTER>` so
every reference `n` (as a FROM target) is replaced with a
table synthesized from the result. The synthetic table
needs a transient `TableStore`-equivalent — either an
in-memory backend or a tempdir provisioned with the outer
engine's handles.

### Isolation qualification (ADR 0276 target)

Deliverable: `docs/reference/BRADIAN_ISOLATION_SCHEDULES.md`
enumerating every snapshot / repeatable-read / serializable
schedule and whether the current engines (SqlEngine,
DomainSqlEngine, MvccSqlEngine, HistorySqlEngine) accept /
reject. Harness: ADRs 0252–0255 supply the fault-injection
primitives; the schedule driver reuses the
`std::thread::Barrier` pattern from ADR 0264's concurrent
test.

### External SQL suite (ADR 0277 target)

Deliverable: new crate `tests/sql-conformance` that reads
a declarative `.test` file format (SQLLogicTest-compatible),
runs each query through the engine, and compares results.
Expected pass-rate is low initially; failures become
tracked gaps.

## Consequences

- P0-3 is "closed on verifiable features" after this run:
  arithmetic, NOT + parens, IS DISTINCT FROM, bare-column
  IS / compare / LIKE / IN / BETWEEN, CAST targets (incl.
  DECIMAL + TIMESTAMPTZ + UUID), CASE, INTERSECT/EXCEPT, IN
  subquery, INNER JOIN. Four items (EXISTS, CTE, isolation,
  external suite) stay OPEN with design notes.
- The Platform Gaps Plan still lists each as a P0-3 slice.
  A future implementer picks one and follows the design
  note above.
