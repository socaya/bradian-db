# G2 exit evidence — `.derc` storage, WAL, manifests, delta, compaction

## Summary

The partition write path is durable and crash-safe. Readers see a snapshot-consistent view
across segments + in-memory delta. Compaction (flush-only in v1) atomically publishes new
segments and truncates the WAL.

## Deliverables

- `.derc` v1 writer + reader (ADR 0002). Covers typed pages, dictionary encoding, zstd
  compression, zone maps, per-page CRC32, atomic footer with CRC32, temp-and-rename segment
  publication.
- Partition WAL (ADR 0003) with CRC32-per-record framing. Replay stops safely at the first
  corrupt or truncated record.
- JSON manifest with CRC32 trailer + `.bak` fallback. Atomic rename + parent-directory fsync.
- Delta memtable with per-key `(source_version)` version fence; replays with lower version
  are dropped idempotently.
- Snapshot handles reference-count the manifest generation so compaction/GC cannot delete a
  file a reader is holding.
- `Partition::snapshot_rows` returns a key-merged view of segments + delta for the runtime
  scan operator.

## Tests at G2 close

- 24 `dap-storage` library unit tests (bitmaps, codecs, zone maps, delta, manifest, WAL).
- 5 segment roundtrip integration tests (happy path, version rejection, payload CRC
  corruption, footer CRC corruption, dict codec selection).
- 5 partition durability integration tests (upsert/delete, WAL replay across restart,
  flush publishes segment + truncates WAL, version fence drops stale replay, snapshot
  generation stamp).

## Known limitations carried forward

- Multi-page column concatenation is implemented but writers only emit single-page columns
  per segment today.
- Compaction merges delta into one segment; multi-segment merging (and delete-vector GC) is
  deferred until workload traces justify the complexity.
